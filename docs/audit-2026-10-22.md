# Auditoría integral CINe — 22 de octubre de 2026

## Alcance y límite de la verificación
Revisión del repositorio GitHub `main`, configuración de Render, permisos de
Supabase PostgreSQL, colas de correo e impresión y pruebas automatizadas.
Los servicios reales se inspeccionan con consultas de solo lectura.
No se enviaron correos, no se modificó el estado empresarial ni se rotaron secretos.
Esta revisión no equivale a una auditoría externa exhaustiva ni a pruebas de penetración.

## Infraestructura observada
- Render: `universal-erp` sobre Python/Gunicorn, una instancia, plan Free,
  despliegues manuales, comprobación `/readyz`, rama `main`.
- Supabase: proyecto `cine-demo`, PostgreSQL 17.11, región `us-east-1`,
  esquema privado `erp_private`, una fila de estado transaccional.
- Estado (a fecha de la revisión): 3 ventas, 2 órdenes, 2 planillas,
  3 correos registrados como enviados, 0 cuentas de personal creadas en la web.
- RLS: habilitado en `state`, `auth_sessions` y `login_attempts`.
  `schema_versions` carece de RLS. Se comprobó que los roles
  `anon` y `authenticated` no poseen USAGE en el esquema ni permisos
  SELECT/WRITE en ninguna de las tablas inspeccionadas.
  El aviso de Supabase debe tratarse como endurecimiento pendiente,
  **no** como una exposición pública confirmada. No alterar RLS en producción
  sin plan de compatibilidad del usuario `erp_app`, respaldo y autorización.

## Hallazgos corregidos en la rama de auditoría
1. **Directorio de impresión desfasado**: las cuentas creadas por Contabilidad
   se consultan dinámicamente desde Supabase para entrar a CINe, pero la
   autenticación de agentes de impresión y la selección de terminales estaban
   atadas al diccionario de cuentas iniciales `ERP_USERS_JSON`. Se unificó
   la lectura del directorio de impresión en modo `agent`; no se modificó
   `ERP_PRINT_AGENTS_JSON` ni se alteró el modo `manual`.
2. **Diagnóstico HMAC falso-negativo**: el `ping` requería que Apps Script
   informase `envio=desactivado`; después de habilitar el correo real,
   podía registrar un aviso confuso de transporte desactivado. Se aceptan
   ambas respuestas autenticadas, sin realizar entregas.
3. **Cobertura incompleta de CI**: se añadió una comprobación de compilación
   y toda la suite Python en pull requests y `main`. El workflow del
   frontend ahora ejecuta tipado, lint y pruebas de interfaz además de
   comparar los bundles compilados.

## Controles preservados
- Sesiones con cookies HttpOnly/SameSite y expiración.
- Validación de rol y sucursal en comandos; contraseña inicial rotatoria.
- Contraseñas almacenadas como hash PBKDF2; ningún secreto en la web pública.
- Correo individual con destinatario aprobado, HMAC, idempotencia y estados
  conservadores ante fallos.
- Impresión de boletos posterior a la transacción de venta, con recibos y
  reintentos acotados.
- Almacenamiento privado sin claves de Supabase en el navegador.

## Mejora estructural futura (requiere proyecto separado)
La base actual conserva colecciones de negocio en un documento JSONB grande,
bloqueado por fila para cualquier actualización. Este diseño funciona para la
carga observada, pero tiene contención potencial y no sustituye un esquema
relacional normalizado con migraciones, constraints y auditoría por tabla.
No migrar destructivamente mientras las ventas y planillas estén operativas.

Otros límites: Render Free no proporciona la disponibilidad ni los recursos
habituales de producción comercial; el envío Gmail está sujeto a cuotas.
El modo de impresión agente todavía necesita configuración técnica de
terminales individuales; crear la cuenta desde la web no aprovisiona
automáticamente una impresora física.

## Antes de fusionar
1. Exigir checks de Python, frontend y correo en verde.
2. Revisar diff para asegurar ausencia de modificaciones a secretos o datos.
3. Fusionar el PR y desplegar Render manualmente.
4. Validar `/readyz`, ausencia de errores y colas sin envíos ambiguos.
